# v9 第一人称房间的视觉尺度

用户希望战斗区域看起来是开阔房间，而不是贴近墙面的窄格子。本轮只修改 `dist/dungeon-view.js`，不改地图生成、移动、遇敌、拾取距离或存档结构。既有 `ROOM_TEMPLATE_EVIDENCE.md`、`ROOM_LAYOUT_NATIVE_EVIDENCE.md` 与 `BATTLE_ZONES_EVIDENCE.md` 的模板内部边和房间/走廊归属继续作为空间约束。

## 逻辑格与建筑空间

- 每个逻辑格投影到 4×4 个视觉单元。房间中的逻辑格使用全部 16 个视觉单元；走廊只保留中央两单元宽的通道，按原有方向连出。
- 原地图的相邻地面不等于可通行。跨逻辑格的视觉连接仍要求原始 `connections` 双向允许；即使两边都是完整房间地面，内部封闭边仍会终止光线。
- 玩家视觉位置为逻辑格中心乘 4。WASD 仍一次移动一格，F 的相邻格规则保持原样。渲染不写入 `state`，因此不会改变游戏路线，也不会重建旧存档。
- 房间继续用紫色地毯、红木书架和木顶；窄走廊铺石地。房间与走廊交界处的墙柱使用木质边框，帮助识别出口。
- 视野系数仍为 0.78，没有通过加宽 FOV 制造空间感。视觉层的墙高 1.6、视点高 0.8，均为独立绘制的原型美术比例，**不是从原版确认的米制尺度**。

普通存档有 `generation.zones` 时按其真实模板格归属区分房间和走廊。旧生成存档使用 `generation.rooms` 外框与地面交集；更早的无模板地图保留原通行拓扑，并把其地面完整扩展，避免猜造新的内部走廊/墙。独立演示战斗的 authored backdrop 不使用游戏地图扩展比例。

## 遭遇和物品

遭遇代表位于逻辑格中心。`state.roomAt(x,y)` 可返回 `visualKey`，优先选用该怪物像素图；未提供时仍使用现有 battle/elite/boss 默认代表。一个地图遭遇只画一个代表，战斗敌群由主界面另行绘制。

箱桶、推车、宝石箱和掉落物使用稳定的格内侧边/角落坐标，优先靠近真实封闭边。位置始终留在原交互格内，实际像素大小按建筑尺度调整。不同格有空间间隔，近处不再占满画面；真实透视下的自然遮挡仍然保留。铲子与洞口继续居中。所有精灵和物品标签使用同一视觉世界的墙体深度；隔墙物体的标签不会被查询或绘制。

## 接口

原有 API 均保持：

```js
DungeonView.draw(canvas, state);
DungeonView.drawBattle(canvas, state); // 相同建筑、位置和朝向，隐藏地图实体/手持灯
DungeonView.drawBackdrop(canvas);     // 无地牢时的独立演示背景
```

新增诊断接口 `DungeonView.sceneFor(state)` 返回：

- `scale=4`、`width`、`height`、`grid`：视觉格网。
- `masks`：按 `y*width+x` 索引的四向通行掩码，仅用于渲染/验证。
- `roomOwner`：同样索引；0 为非房间，正值为模板区域标记。
- `camera: {x,y}`、`anchor(logicalX,logicalY,side=false)`：统一视觉坐标。
- `logicalMask(x,y)`：经双向检查的原逻辑连接。

此接口不是新的移动系统。主界面仍使用原 `run.dungeon` 坐标、无迷雾地图展示和交互。

## 验证

`tests/dungeon-view.test.cjs` 四项测试通过：

1. 20 种子×3层共 60 个场景逐逻辑边检查，视觉边开闭与原地图完全一致；房间格 16 单元，走廊至多 12 单元，观察到 516 个直走廊格为 8 单元；玩家和侧置物品锚点不越逻辑格。
2. 两侧都有地面的封闭内部边仍遮挡远处侧置物品，隔墙标签不被请求。
3. 相同位置的战斗背景与关闭实体后的探索背景逐像素一致；`visualKey` 能改变遭遇代表。
4. 四个方向绘制及旧地图绘制都不修改原始状态。

`preview-room-scale-v9.png` 是真实生成的 2×2 战斗区域的 800×450 原始像素预览，已检查：房间地毯、天花板、书架墙面、窄出口及单个怪物代表均可见。该预览采用画布 mock 读取像素，文字与页面布局由主任务做浏览器验收。首次 800×450 本地渲染约 31 ms，仅为本机单次观察，不保证浏览器所有帧耗时。

主界面为底部卡牌保留空间，战斗背景画布在CSS中使用较短的显示区域；建筑、逻辑摄像机位置与朝向不更换，显示纵横比例属于原型UI适配。
