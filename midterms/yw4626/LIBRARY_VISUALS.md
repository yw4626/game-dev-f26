# Library rendering v0.7

The user supplied two original-game screenshots showing exploration and combat in the same redwood library, with bookcases, a purple carpet, wood ceiling, and warm highlights. These screenshots guide the palette and composition. All texture pixels are generated by the prototype; no original texture or sprite assets are copied.

## Renderer

- `DungeonView.draw(canvas, state)` remains the exploration API. Existing maps, grid walls, per-edge room connections, billboard sprites, discovered-object labels, secret cracks, and the held lantern remain supported.
- `DungeonView.drawBattle(canvas, state)` renders the same camera and surfaces, suppressing world entities, labels, and the held lantern so the app can place battle enemies and cards in front.
- `DungeonView.drawBackdrop(canvas)` renders a fixed library chamber when no dungeon state exists. `drawBattle(canvas)` automatically uses this fallback.
- `draw(canvas, state, {entities:false, lantern:false})` is the equivalent low-level background call.

World-coordinate textures remain stable when turning or moving. Bookcases use deterministic book colors, spine height variation, gilded bands, redwood rails and pillars; occasional wood panels carry small brass wall candles. Coffered wood ceilings use perspective sampling. Purple carpet follows connected floor tiles, with gold edging and stone margins beside closed walls. Lighting falls off with distance and gives nearby shelves a warm tint. Texture caching is bounded.

Supply carts are separately drawn wooden cart silhouettes with wheels: `manaCart` has blue contents and `bracerCart` gold/leather contents. Revealed pickups map `reward.kind: mana` to a blue orb and `reward.kind: deal` to a bracer. These sprites communicate the configuration rules integrated by the main task; the renderer itself does not award bonuses. All four new cart/drop sprites were checked for distinct pixel output and preserved item labels.

## Validation

Syntax validation passed. Renderer checks cover all three floor palettes/seeds and four camera directions; opaque image output is preserved. Visible-object labels still render, while labels behind a wall are never queried. Combat suppresses entity callbacks and produces the same surface pixels as exploration with entities disabled. The standalone combat fallback equals `drawBackdrop` output. The local mock renderer averaged 5.37 ms at 480×270 across twelve renders; this is a local timing observation, not a browser performance guarantee.

`preview-library-v7.png` is the 800×450 procedural backdrop preview inspected during implementation. Final app layout and browser screenshot verification belong to the main integration task. Exact original room geometry, balcony architecture, lighting, and screen composition are not claimed to be reproduced by this texture adaptation.
