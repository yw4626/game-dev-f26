# v8 房间战斗区块与走廊留白

本轮复用 `ROOM_TEMPLATE_EVIDENCE.md`、`ROOM_LAYOUT_NATIVE_EVIDENCE.md`、`LARGE_MAP_EVIDENCE.md` 及其已保存的资源/原生证据，没有再次完整反编译或修改原游戏。

## 已确认结构与本轮适配

原始 RoomTemplate 有真实格子范围、内部四向路径、出口候选、出生点和多个事件候选。普通 2×2 模板可在四格各含 EventType=1，条件包括“不是地图出生点”；物理房间不等于单个战斗点。旋转与吸附、MST/额外连边、出口开放和模板内部连接的证据保持不变。原版的弹簧目标间隔为 1.75，但吸附验证只禁止正面积重叠，不能声称原版强制保留一格墙。

旧原型将 8 个事件按全图路径距离散落，候选甚至包括走廊。v8 在不增加格网、不改模板内部边、不增加遭遇数量的前提下，给每个物理模板指定角色：

- 两个普通房间为战斗区，四场普通/精英遭遇按阶段分为 2+2。
- 出生所在普通房间为补给休整区，集中商店、营地、宝箱三个服务事件。
- 终点房间为守关区，守关事件仍使用原始终点模板的 EventType=3 坐标。
- 走廊不放事件、箱桶、宝石箱或推车；保留连接功能。

**以上角色分配、2+2 遭遇安排和服务集中是原型可读性适配，不是完整恢复原版 EventGenerationLayer。** 战斗位置优先模板事件候选，并在同一区块内拉开路径距离；必要时使用该模板内的其他真实可走格。出生点仍来自原始普通模板的出生候选，不使用终点房间出生点。

放置阶段先尝试真实模板之间至少一格间隔，前 48 次不接受相接外框；其后允许原有的“不重叠”布局以免有限地图无法生成。总重试上限仍为 128，最大尺寸仍是原有 12×12、14×14、14×14。`roomsSeparated` 表示本次是否满足优选间隔；它不是原版保证。

## 补给与空地

普通箱桶从每层 4 个减少为 2 个，保留原有 2～10 金币、单层最多一份鸡肉及第二层优先鸡肉规则。另预留两格给宝石箱、两格给法力车/护腕车，共 6 个物品位置。主流程仅在这些已连通、未占用的预留格生成对应物件。

每个区块在事件/物品分配前保留一个空格：出生区保留出生格，其余区块优先保留已使用出口格。补给格优先分散到不同房间并与已有占用位置保持距离，不能侵占保留空格。因此每个模板都至少有一个没有事件或物品的地面格。暗门继续不生成。

## UI 接口（均为屏幕坐标，y 向下）

`d.generation.zones` 每个模板一项：

```js
{
  id: 'zone-0',
  role: 'battle', // battle / boss / service
  name: '战斗区 1',
  entry: false,
  roomIndex: 0, // generation.rooms 中的实例索引
  templateId: 'RT_...',
  cells: [{x, y}], // 此模板内实际可走格；不包含角落墙或走廊
  bounds: {x, y, width, height},
  eventIds: ['1-0-0', '1-1-1'],
  clearCells: [{x, y}], // 必须留空的格子
  supplyCells: [{x, y}] // 本区全部预留物品位置
}
```

- `d.rooms['x,y'].zoneId`：事件归属。
- `d.generation.corridorCells`：模板以外的可走连接格。
- `d.generation.supplySites`：仅供两辆推车使用的两个空位。
- `d.gemSites`：宝石箱位置，维持既有接口。
- `generation.rooms`、`paths`、MST、源模板哈希和来源楼层配置接口保持不变。

这些元数据不是迷雾权限。UI 必须按现有 `seen` 过滤格子和事件，不能因拿到整个 `zones` 就揭示未探索区域。

新地图 `version=8`、算法 `room-template-spring-mst-zones-v1`。加载旧存档不会重新生成地图，不给旧地图强行套用分区；旧网格、事件位置和物品状态原样保存，后续新楼层才采用新生成器。

## 验证结果

完整测试输出保存于 `validation-v8-tests.txt`：**121 项全部通过，0 失败**。

- 新增 100 种子 × 3 层的 300 张地图检查：四个模板区块、角色/事件数量、所有事件及物品可达、无重叠、走廊留白、每区保留空地。300 张都满足优选房间间隔，最大生成尝试 5 次，最少 6 个走廊格。这是本测试样本结果，不是所有随机种子的保证。
- 30 种子 × 3 层的 90 张主流程地图检查：恰好两个推车，位置严格等于 `supplySites`；总计六个物品，走廊和保留空格均无物件。
- 原有 300 张连通测试和 50 张旋转模板逐格内部边校验继续通过。
- 版本 6 结构兼容测试证明读档不会重造地图；既有旧版本迁移测试继续通过。
- 8 条生成地图的完整旅程全部通关，合计 461 次移动、24 次商店访问和 48 次挖掘步骤；另外既有 v8 双起始牌组旅程、XP 选牌旅程及失败分支测试也通过。
- 主流程修复营地/商店脚下事件优先交互；完成后的营地不再重复服务，但允许继续操作前方推车。对应回归测试按该语义验证一次性服务，而非禁止一切后续交互。
